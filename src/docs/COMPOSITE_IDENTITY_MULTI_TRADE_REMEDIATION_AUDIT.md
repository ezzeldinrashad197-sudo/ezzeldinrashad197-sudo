## 1. Executive Summary

The Multi-Trade Remediation has been successfully implemented and verified across all register families. The pipeline now strictly obeys the **NON-NEGOTIABLE GOVERNANCE CONTRACT**:

$$\mathbf{ROW\text{-}LEVEL\ EXPLICIT\ TRADE\ EVIDENCE} > \mathbf{COMPOSITEIDENTITY\ CONTAINER\ FALLBACK} > \mathbf{UNCLASSIFIED}$$

### Dual Governance Objectives Achieved
1. **Register Identity Preservation (File/Worksheet Level):** Homogeneous register files (e.g., `WIR-ARCH.xlsx`) preserve their container discipline (`ARCH`) when individual row discipline cells are blank or generic (`GEN`).
2. **Row-Level Trade Separation (Multi-Trade Registers):** Multi-trade registers (e.g., master workbooks containing `ARCH`, `STR`, `MECH`, `ELEC`) preserve explicit row-level trade declarations without being forcibly overwritten or collapsed by file/worksheet-level container metadata.

## 2. Root Cause & Solution Summary

### The Root Cause
Previously, `resolveTradeFromRow()` checked container-level composite identity (`compDisc`) at Step 1 before inspecting row-level explicit discipline (`explicitDisc`). Consequently, if a file had a container identity (e.g., `ARCH` or `GEN`), Step 1 triggered for **ALL** rows in the file, bypassing Step 3 (`explicitDisc`) and forcibly locking every row to the container trade.

### The Applied Solution
`resolveTradeFromRow()` was updated in `src/utils/calculations.ts` to reorder the precedence stack:
1. **Step 1:** Explicit Row Discipline (`explicitDisc`) — if specific (not `GEN`/`GENERAL`/`UNCLASSIFIED`), wins immediately.
2. **Step 2:** Explicit Row Trade Field (`tradeField`) — if specific, wins immediately.
3. **Step 3:** Container Composite Identity Fallback (`compDisc`) — used for rows that are blank, generic (`GEN`/`GENERAL`), or unclassified at the row level.
4. **Step 4:** LogType / Source Identity String fallback.
5. **Step 5:** Zero-Invention Fallback — returns `UNCLASSIFIED` (`UNCLASS`).

## 7. Full End-to-End Analytics Pipeline Verification

### Downstream Pipeline Trace (Raw Data -> Canonical Dataset -> Analytics Metrics)
To verify that trade separation is preserved all the way through the analytics layer, real multi-trade register datasets were traced across every stage of the pipeline:

1. **Parser Layer (`parseExcelFile`):** Extracts explicit row-level discipline strings alongside the file/sheet `CompositeIdentity`.
2. **Normalization Layer (`normalizeData` / `resolveTradeFromRow`):** Applies the precedence rule. Row-level explicit discipline wins over file `CompositeIdentity`. Generates canonical `documentType` (e.g. `WIR-ARC`, `WIR-STR`, `WIR-MEC`, `WIR-ELE`).
